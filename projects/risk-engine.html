Scoring AI agent actions before they run

A fine-tuned ModernBERT encoder that looks at what an AI agent is about to do, what it says it is doing, and the untrusted text around it, then returns a calibrated risk score. Built for SecretZero at SecurITaaS Pte Ltd.

This is proprietary SecurITaaS work, so this page covers the approach only. There is no public code, data or model, and product specifics are left out. I'm happy to go deeper in conversation.

The problem

Rules can say which actions an agent may take, but not whether a specific call makes sense. An agent that was asked to remove access but quietly grants more, or one that obeyed an instruction hidden in a ticket or a tool output, can pass every static rule. The risk engine adds a second opinion: does this action match the stated intent, and did untrusted content try to steer it?

How it works

One shared encoder feeds three heads. A sequence head checks whether the stated intent and the action agree. A token-level head marks text that looks like an injected instruction, so the score can point at the exact span. A third pass reads the intent alone and predicts the operation, which gives an independent cross-check. The combined, calibrated score goes to a deterministic policy. The model adds friction but never grants permission on its own, and if it is unavailable, the system fails closed and asks a human.

How I trained it

  • Labels by construction. There was no labelled traffic, so every training example is generated in a way that fixes its label. For example, an injection is inserted into an untrusted field and its exact characters are labelled. No model ever decides a label.
  • No leakage. Data is split by template, not by example. The test set only contains phrasings and attack patterns the model never saw in training.
  • Hard negatives. Benign text full of trigger words ("ignore the warning", "override approved") is labelled clean, so the model cannot get by on keywords.
  • LLM paraphrases, validated. A local LLM rewrote templates in many styles, from terse to formal to non-native English. Each rewrite was checked automatically before use and inherits its source template's split.
  • Licence-checked public data added real-world injection attempts. A dataset with no stated licence was left out.
  • Production path: temperature calibration, thresholds set on a separate calibration split, ONNX export, signed releases, and CPU serving.

What went wrong, and what I changed

  • The first run overfit. Training loss went to zero while held-out injection recall dropped. Fewer epochs, a lower learning rate and harder negatives fixed it.
  • INT8 quantization shifted the model's outputs too far to be usable, so it serves at full precision. Latency is about 200 ms on a CPU, which is fast enough for an approval path.
  • A real-world paraphrase triggered a false hold. Adding validated paraphrase data cut false holds on legitimate requests from 14% to 5% on the test set.

Limits

All results come from held-out synthetic templates. They show that the model generalizes to unseen phrasings, not that it catches every real attack. The next step is a human-labelled evaluation set from real traffic. Until then, the model's role is to route risky calls to a person, which is also the safe way to deploy any classifier in front of agents.

The public mcp-authz-gateway shows the enforcement side of the same idea: policy, human approval and audit for agent tool calls.
